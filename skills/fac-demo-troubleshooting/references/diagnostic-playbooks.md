# 分步诊断剧本

## A. 构建失败

1. 保存完整日志，确认失败发生在哪个目录和目标。
2. 检查 shell 脚本行尾；若有 `^M`，先归一化。
3. 检查编译器与 Python 版本；确认 gcc/gfortran 混编环境。
4. 若失败在 Fortran 符号链接，检查 ABI 宏与 configure 选项。
5. 若失败在扩展模块构建，检查 `setup.py` 生成文件与构建目录。
6. 只修复被证实的原因；重跑同一目标验证。

## B. 导入失败

1. 打印 `PYTHONPATH` 与 Python 版本。
2. 列出实际 `build/lib...` 目录，确认扩展文件名。
3. 最小导入四个模块，记录具体异常。
4. 符号错误查 ABI；版本错误查 Python；路径错误查环境变量作用域。
5. 验证：最小导入成功，再跑低资源回归。

## C. 运行崩溃

1. 记录命令、退出码、日志与当前输出目录。
2. 判断是否为二阶段工作流；检查第一阶段文件是否完整。
3. 检查是否在共享目录中并发写同名表。
4. 检查是否被误加 `openmp` 参数或 MPI 初始化冲突。
5. 用最小输入复现；不要先改物理参数。
6. 验证：修复后重跑崩溃步骤并跑相关回归。

## D. 比对失败

1. 保持结果文件名不变，确认扩展名分派正确。
2. 比较表头：`NBlocks`、`E0`、版本/时间戳、块数。
3. 检查行序是否变化，是否由排序函数处理。
4. 检查容差与死键；通过也要识别“通过但弱验证”的列。
5. 检查单位与列语义；确认 ASCII/二进制差异。
6. 最后才审视物理实现；不得直接改基准或放宽容差。
7. 验证：单项比对通过，且相关表检查无新异常。

## E. 无基准任务

1. 确认目录确实没有官方基准。
2. 检查所有预期表是否生成、大小非零、文件头一致。
3. 检查能量范围、能量点、温度密度网格。
4. 检查速率/截面非负、谱强度口径、物理趋势。
5. 报告“无官方基准，执行产物与物理合理性检查”。

## F. 长耗时任务

1. 确认是否被排除在每日检查之外。
2. 记录开始/结束时间、墙钟、脚本内部计时。
3. 检查阶段产物是否按预期增长。
4. 单独调度，独立日志与输出目录。
5. 完成后核对退出码、文件数量与体积；不要中途清理现场。

## G. 结果异常但程序成功

1. 先看单位、列语义和 `TYPE` 字段。
2. 再看输出行序与索引对应关系。
3. 检查注释与代码是否冲突。
4. 用物理趋势和文献量级做交叉验证。
5. 若仍需改代码，区分运行适配与物理改动，并写明验证依据。
