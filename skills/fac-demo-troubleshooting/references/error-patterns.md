# 错误模式库

每条按“症状 → 原因 → 处理 → 验证”组织。定位时从环境类问题开始，逐步向物理实现靠近。

## 1. CRLF 行尾

- 症状：`/bin/sh^M: bad interpreter`、`configure` 无法执行。
- 原因：Windows 行尾破坏 Linux shell 脚本。
- 处理：在独立工作目录归一化 `configure`、`config.guess`、`config.sub`、`install.sh`、`mkinsdir.sh`。
- 验证：`./configure` 可执行，生成的 Makefile 无 `^M`。

## 2. C/Fortran ABI

- 症状：链接失败、Fortran 符号未定义、LOGICAL 传参异常。
- 原因：C/Fortran 名字修饰或参数传递约定不匹配。
- 处理：检查 configure 的桥接选项；必要时在生成后的 `sysdef.h` 启用 `f2cFortran`。
- 验证：库与四个扩展模块链接成功，导入检查通过，回归不引入新差异。
- 物理影响：无；只影响 ABI。

## 3. 导入路径与 Python 版本

- 症状：`ModuleNotFoundError`、`ImportError`、找不到 `build/lib.../pfac`。
- 原因：`PYTHONPATH` 未包含构建产物与 Python 包目录，或 Python 版本与扩展不匹配。
- 处理：用 `ls` 确认真实构建路径；设置 `PYTHONPATH`；使用匹配版本 Python。
- 验证：`from pfac import fac, crm, pol, util` 成功。

## 4. Python 2 → 3

- 症状：`print`、`cPickle`、`Numeric`、`biggles`、`has_key` 等报错。
- 原因：旧脚本使用 Python 2 语法或导入。
- 处理：只改语法、导入和包兼容；不改物理参数、组态或网格。
- 验证：脚本退出码 0，产物表头与基准一致。

## 5. OpenMP/MPI 参数差异

- 症状：传 `openmp` 后行为不变、行序变化、MPI 初始化失败。
- 原因：脚本没有参数分支，或硬编码不同线程数。
- 处理：查看脚本入口，按真实支持方式运行；不要用统一假设。
- 验证：退出码 0；比对时用排序后的检查函数。

## 6. PFAC 非线程安全

- 症状：多任务结果交错、偶发崩溃、状态污染。
- 原因：一个 Python 解释器内并发调用共享 C 全局状态。
- 处理：改用独立进程、独立输出目录、独立日志。
- 验证：每个进程结果与单进程一致。

## 7. 缺前置产物

- 症状：二阶段脚本段错误、找不到 `.b*`/`.d*` 或靶态文件。
- 原因：第一阶段未运行或产物不完整。
- 处理：先跑第一阶段，核对文件存在性、大小和文件头，再跑第二阶段。
- 验证：第二阶段正常写出结果；不是通过改物理开关解决。

## 8. 比对失败

- 症状：`check.py` 非零退出、数值差异。
- 原因：扩展名分派、`E0`/`NBlocks`、行序、容差、死键、单位或列语义。
- 处理：按 `checkpy-contract.md` 逐项排查；不要先更新基准。
- 验证：定位原因后重跑单项比对，并跑相关回归。

## 9. 无官方基准

- 症状：目录没有基准表，`make check` 不适用。
- 原因：任务资源消耗大或没有发布基准。
- 处理：做产物完整性、正值性、能量网格、趋势和量级检查。
- 验证：明确记录“无官方基准，执行物理合理性检查”。

## 10. 长耗时与超时

- 症状：任务跨小时、输出 GB 级、似乎卡住。
- 原因：大 CI 基组、多电荷态、多温度点或多阶段任务。
- 处理：单独调度；记录墙钟与脚本内部计时；核对阶段产物是否持续增长。
- 验证：退出码 0、产物数量与体积合理、阶段日志完整。

## 11. 单位与列语义误读

- 症状：数值相差固定因子、谱强度口径混乱、截面量级错误。
- 原因：ASCII eV 与二进制 Hartree 混用、CE/EII π 因子、SP `strength` 随 `TYPE` 变化、读取器键名误命名。
- 处理：查表头、源码输出路径与单位参考；先确认语义再换算。
- 验证：换算前后与表定义一致。

## 12. 文档与代码矛盾

- 症状：注释能量、脚本名、基准版本、能量范围与代码不一致。
- 原因：历史注释未同步。
- 处理：以实际函数调用、输出文件头和实测记录为准；更新文档说明，不改物理代码。
- 验证：代码值与输出头部互相印证。
