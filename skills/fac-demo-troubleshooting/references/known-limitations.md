# 已知限制索引

本文件记录会影响解释和验证的抽象限制。遇到同类现象时先判断是否属于这些限制，避免误判为新的物理问题。

## 1. PFAC 非线程安全

一个 Python 解释器进程内不能并发调用同一 PFAC 实例；并行必须进程级且隔离输出。并行导致的行序变化应由比对函数处理。

## 2. 比对死键

容差字典键名必须匹配读取器列名。历史上存在拼写错误或列名不匹配，使相对容差不生效；此时“通过”只说明绝对容差或默认值下通过。

## 3. 版本与时间戳

基准文件声明版本与文件头版本可能不同；`check.py` 通常忽略版本与 `TSess`。不要据此判断物理结果错误。

## 4. 弱线容差

谱表弱线使用极小绝对容差配合相对容差。通过不代表绝对量级可忽略；失败也不一定意味着物理错误。应同时看绝对差和相对差。

## 5. 无官方基准

部分高资源或多阶段任务没有基准。不得写“自动回归通过”；只能报告产物完整性与物理合理性检查。

## 6. 输入依赖不可颠倒

二阶段工作流中第一阶段产物是第二阶段物理输入。缺文件的崩溃是工作流问题，不是物理算法错误。

## 7. 单位与键名

ASCII 与二进制能量单位不同；截面单位按表类型变化；谱表 `strength` 随 `TYPE` 变化；读取器键名存在历史误命名。换算前必须确认列语义。

## 8. 注释与代码不一致

脚本注释、旧文档或基准说明可能与代码值不一致。以实际调用、输出文件头和实测记录为准。

## 9. Python 2 风格脚本兼容

旧脚本可能依赖 Python 2 语法与包。语法/导入适配不改变物理，但必须记录；不要顺手调整物理参数。

## 10. 耗时口径

日常检查不记录耗时；长任务可同时记录墙钟与内部计时。两者不可混用，也不能从退出码推断速度。
