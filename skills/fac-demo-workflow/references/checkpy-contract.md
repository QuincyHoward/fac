# check.py 通用契约

## 1. 分派规则

`demo/check.py` 按文件名尾部或扩展名分派，常见映射：

| 文件尾 | 检查函数 | 主要对象 |
|---|---|---|
| `.en` / `lev` | `check_en` | 能级、块数、`E0` |
| `.tr` | `check_tr` | 辐射跃迁、能量、`gf`、速率 |
| `.ce` / `ceM` | `check_ce` | 碰撞激发、磁子态比值 |
| `.ci` | `check_ci` | 碰撞电离 |
| `.rr` | `check_rr` | 辐射复合与光电离 |
| `.ai` | `check_ai` | 自电离与 DC 强度 |
| `.sp` | `check_sp` | 谱表、布居、发射强度 |
| `.rt` | `check_rt` | 速率矩阵 |
| `.ham` | `check_ham` | 哈密顿量矩阵 |

未知扩展会抛 `TypeError`。不要重命名结果文件，也不要用 `.txt` 直接调用 `check.py`，除非扩展了分派逻辑。

## 2. 表头与默认容差

- `_check_header()` 主要检查 `NBlocks` 相等和 `E0` 相对误差约 1%。
- 版本字段与 `TSess` 时间戳通常忽略；基准版本声明与文件头不一致不一定表示失败。
- `_check_block()` 对数值默认 `atol=1e-8`、`rtol=1e-5`；字符串数组逐字相等。
- 分类容差按表类型设置：能量、碰撞强度、截面、`gf`、速率、谱弱线、哈密顿量各有不同；不要凭经验统一放宽。

## 3. 行序重排

- OpenMP/MPI 可能改变输出行序。
- `check_ai/tr/ce/ci/rr` 会按能级索引或束缚/自由索引重排后比对。
- 不要手工重排基准文件；那会破坏索引语义。

## 4. 死键与拼写风险

- 容差字典的键必须与实际读取器列名一致。
- 历史问题包括 `ratio collision strength` 拼写错误，以及 `rate` 与实际列 `AI rate` 不匹配。
- 死键会导致相对容差不生效，只由默认值或绝对容差兜底；比对通过不代表该列被严格验证。
- 报告结论时应明确“通过但受死键影响”，并保留修复建议，不在排障时顺手改比对逻辑。

## 5. 无基准处理

无官方基准时：

1. 检查文件存在、大小非零、文件头一致。
2. 检查能量范围、能量点数量、温度密度网格。
3. 检查碰撞强度、速率、截面非负且量级合理。
4. 检查谱线强度口径与物理趋势。
5. 明确写“无官方基准，执行产物与物理合理性检查”，不要写“回归通过”。

## 6. make ref 风险

`make ref` 会用当前结果覆盖基准。仅在确认物理正确、环境一致、差异原因明确时使用；否则会掩盖回归信号。

## 7. 耗时口径

- 日常 `check.py` 不记录耗时。
- 长任务可同时存在端到端墙钟和脚本内部 `Total Time` / `Time`；两者口径不同。
- 未记录时写“耗时未记录”，不要从退出码推断速度。
